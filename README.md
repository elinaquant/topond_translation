# TOPOND GUI — шпаргалка по кнопкам

Коротко: что нажимать и что получится. Полная документация — в [README_details.md](README_details.md).

Запустите файл `topond_gui.py`. Все три вкладки доступны сразу, а пути между шагами подставляются автоматически.

## Внизу окна

- **«Остановить»** — прервать текущий расчёт.
- **«Открыть папку результата»** — открыть папку, куда только что всё сохранилось.
- **Журнал** — показывает ход работы и ошибки.
- **Команда** — показывает, что именно сейчас выполняется.
- **Прогресс** — показывает, что программа работает.

---

## Вкладка 1. «Очистка .out»

1. В поле **«Входной .out:»** выберите сырой файл расчёта. Удобнее всего через **«Обзор…»**.
2. В поле **«Выходной .out:»** проверьте, куда сохранять. Имя подставляется само, но его можно изменить через **«Сохранить как…»**.
3. При необходимости поставьте галочки:
   - **«Подробный отчёт»** — показать больше подробностей о склейке файла.
   - **«Проверить результат»** — дополнительно проверить, что ничего не потерялось.
4. Нажмите **«Очистить .out»**.

Что получится: один чистый `.out` без перемешанных дублей. После успеха путь к нему сам появится на вкладке **«2. PDB и BPs»**.

---

## Вкладка 2. «PDB и BPs»

1. В поле **«Входной .out:»** выберите очищенный файл. Обычно он уже подставлен сам.
2. В поле **«Папка результатов:»** выберите папку для PDB. Можно нажать **«Обзор…»**.
3. Выберите, что делать с координатами критических точек:
   - **«Без изменений»** — оставить как в файле.
   - **«Обернуть в ячейку»** — перенести точки внутрь ячейки.
   - **«Совместить с атомами»** — сдвинуть точки к той же ячейке, что и атомы. Обычно лучший вариант для VMD и JSmol.
4. В поле **«Элемент для CP:»** обычно оставьте `X`.
5. Галочку **«Не удалять дубликаты»** ставьте только если дубликаты действительно нужны.
6. Если нужна симметрия, заполните блок **«Симметрия»**:
   - В поле **«Пространственная группа:»** вставьте полный символ без пробелов, например `P12_1/n1`.
   - Нажмите **«Справочник групп…»**, если символ неизвестен. В окне справочника можно дважды щёлкнуть по строке или выбрать строку и нажать **«Вставить символ»**. Закрыть окно — **«Закрыть»**.
   - Галочка **«Показывать все 530 установок в справочнике»** показывает не только 230 основных, но и все варианты установок.
   - **«Допуск симметрии»** обычно оставьте `0.001`.
   - **«Образ bond paths»**:
     - **«shift»** — не разрезать линии на границе ячейки;
     - **«cut»** — разрезать линии по границе.
7. При необходимости измените **«Порог угла для calc BPs»**. Обычно это `140` градусов.
8. Нажмите **«Создать PDB и BPs»**.

Что получится в папке результатов:

- `cell.pdb` — структура;
- `critical_points.pdb` — все критические точки;
- `crystal_BPs.pdb` — связи из TOPOND;
- `calc_BPs.pdb` — достроенные связи;
- `summary.txt` — краткая сводка;
- файлы `*_symm.*` — то же самое, размноженное по симметрии.

После успеха папка результатов сама появится на вкладке **«3. Суперячейка»**.

---

## Вкладка 3. «Суперячейка»

1. В поле **«Папка с PDB:»** проверьте папку из предыдущего шага. Обычно она уже подставлена.
2. В поле **«Папка результата:»** проверьте, куда сохранять суперячейку.
3. В блоке **«Источник файлов»** выберите:
   - **«Симметрийные *_symm.pdb»** — если на шаге 2 вы задавали пространственную группу;
   - **«Базовые файлы»** — если симметрия не нужна.
   - Если не выбирать вручную, программа сама поймёт, какие файлы есть в папке.
4. Нажмите готовый пресет:
   - **«1×1×1»** — одна ячейка;
   - **«3×3×3»** — три ячейки по каждому направлению;
   - **«3×3×1»** — три по `a`, три по `b`, одна по `c`.
5. Если нужен свой размер, выберите режим в блоке **«Размер и положение бокса»**:
   - **«Дробные координаты»** — размер задаётся в долях ячейки. Поля **«Центр (доли ячейки)»** и **«Смещения от центра»**; ширина `1.0` — одна ячейка.
   - **«Ангстремы»** — размер задаётся в Å. Заполните **«Центр (Å)»**, **«Смещения (Å)»** и выберите оси:
     - **«вдоль a,b,c»** — по осям ячейки;
     - **«вдоль x,y,z»** — по декартовым осям.
6. Нажмите **«Построить суперячейку»**.

Что получится: PDB-файлы `*_supercell.pdb` и сводка `summary_supercell.txt`.

---

## Если буквы отображаются как `\u041e`

Это не ошибка расчёта, а неподходящий Python для окна. GUI обычно исправляет это сам. Если нет — смотрите раздел про шрифты в [README.md](README.md).
