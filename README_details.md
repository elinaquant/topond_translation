# Экспорт критических точек TOPOND → VESTA / VMD / JSmol

Основной скрипт `topond_cp_export.py` берёт «сырой» текстовый вывод программы
CRYSTAL17 (файл `.out` с разделом TOPOND) и превращает его в аккуратные файлы,
которые открываются визуализаторами — чтобы было видно, **где в кристалле
находятся критические точки** (связи, кольца, каркасы, атомы).

> Для построения суперячейки из уже готовых PDB-файлов (`cell.pdb` и
> `critical_points*.pdb`, `*_BPs*.pdb`) используйте отдельный скрипт
> `make_supercell.py` — см. раздел
> [«Суперячейка (`make_supercell.py`)»](#суперячейка-make_supercellpy).

Интернет не нужен. Установка не нужна. Только Python 3.10+ и стандартная
библиотека.

> Примеры ниже относятся к файлу `CP_BPs_dedup_final.out` — это новый формат
> с найденными `(3,-3)`-аттракторами. Старый `CP.out` тоже поддерживается.

---

## Как запустить (30 секунд)

Откройте терминал в папке проекта и введите:

```bash
python topond_cp_export.py CP_BPs_dedup_final.out --outdir results --align
```

Где `CP_BPs_dedup_final.out` — ваш файл с выводом CRYSTAL17, `results` — папка,
куда сложатся результаты (создастся автоматически). Флаг `--align` нужен,
чтобы точки встали поверх атомов — без него они могут выглядеть со смещением
(подробности ниже).

Если нужны координаты **без изменений, как в исходном файле** — уберите флаг:

```bash
python topond_cp_export.py CP_BPs_dedup_final.out --outdir results
```

**На выходе вы увидите нечто вроде такого:**

```
Cell (angstrom / degrees):
  a=7.62270  b=13.94640  c=16.01610  alpha=90.0000  beta=101.6439  gamma=90.0000

Atoms in cell: 108
CP total: 132 (unique, duplicates removed)
  BCP (3, -1) residue CPM1: 49
  RCP  (3, 1) residue CPP1: 43
  CCP  (3, 3) residue CPP3: 13
  NCP  (3, -3) residue CPN3: 27

Aligned to the atom cell: 40 of 132 CP translated (lattice vectors: (1,0,0)x20, ...)
Crystal BPs: 35 lines (found 40, kept 35) -> crystal_BPs.pdb
Calc BPs: 53 lines (candidates 72, added 53, angle >= 140 deg) -> calc_BPs.pdb

Files created:
  results/cell.pdb
  results/critical_points.pdb
  ...
```

Это просто отчёт: размеры ячейки, сколько атомов и сколько точек какого типа
нашлось, и какие файлы появились. То же самое сохраняется в
`results/summary.txt`.

## Графический интерфейс (`topond_gui.py`)

Для пошаговой работы без запоминания флагов есть русскоязычный GUI. Запуск
из папки проекта:

```bash
python3 topond_gui.py
```

Ничего дополнительно устанавливать не нужно, если в Python уже есть
`tkinter` (в большинстве сборок есть; в Debian/Ubuntu при необходимости —
`sudo apt install python3-tk`). Для справочника пространственных групп нужен
`spglib` — тот же, что и для `--space-group`.

Все три вкладки доступны сразу, переключаться между ними можно в любом
порядке:

1. **«1. Очистка .out»** — входной и выходной `.out`, флаги `--report` и
   `--verify`. По умолчанию предлагается `<имя_входного>_dedup.out`.
2. **«2. PDB и BPs»** — входной `.out`, папка результатов, режим координат
   (`raw`, `--wrap`, `--align`), `--dummy-element`,
   `--keep-duplicates`, пространственная группа, `--symmetry-tol`,
   `--symmetry-image` (`shift`/`cut`), `--bp-angle` и справочник групп
   (`--list-space-groups`; галочка `--all-settings` показывает все 530
   установок).
3. **«3. Суперячейка»** — папка с PDB и папка результата, источник
   `symm`/`base`, пресеты `1×1×1`, `3×3×3`, `3×3×1`, дробный или
   ангстремный режим, `--ang-axes` и все поля `--center-*`/`--range-*`.

GUI сам подставляет логичные пути между шагами (очищенный `.out` → экспорт →
папка `results` → суперячейка), но не перезаписывает путь, который вы ввели
или выбрали вручную. Источник для суперячейки выбирается автоматически:
`symm`, если в папке есть все `*_symm.pdb`, иначе `base`.

В нижней панели видны фактическая команда, журнал выполнения, статус и
прогресс; процесс можно остановить кнопкой **«Остановить»**, а после
завершения — открыть папку результата. Скрипты запускаются отдельными
процессами через рабочий Python (по возможности тот, где есть `spglib`),
без `shell`; сами `dedup_cp_bps.py`, `topond_cp_export.py` и
`make_supercell.py` не изменяются.

Если вместо русских букв видны последовательности вида `\u041e`, значит Tk
в текущем Python собран без Xft/fontconfig (так бывает в некоторых
conda-сборках). GUI автоматически перезапустит окно через системный Python
с Unicode-шрифтами, но рабочие скрипты оставит на Python со `spglib`. При
необходимости интерпретаторы можно задать явно:

```bash
TOPOND_GUI_PYTHON=/usr/bin/python3 \
TOPOND_WORKER_PYTHON=/path/to/python-with-spglib \
python3 topond_gui.py
```

## Что появится в папке `results`

| Файл | Что внутри | Зачем нужен |
|---|---|---|
| **`cell.pdb`** | атомы вашего кристалла + рамка ячейки | «сама структура» |
| **`critical_points.pdb`** | все критические точки | **главный файл**, точки поверх структуры |
| `critical_points.xyz` | те же точки, упрощённый формат | запасной вариант |
| `critical_points_3m1.xyz` | только точки связей (BCP) | если нужны только связи |
| `critical_points_3p1.xyz` | только точки колец (RCP) | |
| `critical_points_3p3.xyz` | только точки каркаса (CCP) | |
| `critical_points_3m3.xyz` | только атомарные точки (NCP) | |
| **`crystal_BPs.pdb`** | линии BCP → найденный `(3,-3)`-аттрактор | «кристаллические» связи из TOPOND |
| **`calc_BPs.pdb`** | линии BCP → ближайшее ядро (если не найдено в `crystal_BPs` и угол ≥ `--bp-angle`) | достроенные связи |
| `critical_points_symm.*` | те же CP, размноженные по `--space-group` | полная ячейка |
| `crystal_BPs_symm.pdb` | симметрийные `crystal_BPs` | полная ячейка |
| `calc_BPs_symm.pdb` | симметрийные `calc_BPs` | полная ячейка |
| `summary.txt` | текстовый отчёт и диагностика отбраковки | |

Без `critical_points.pdb` никуда; остальное — приятное дополнение.
`crystal_BPs.pdb` и `calc_BPs.pdb` создаются при каждом запуске (отдельной
опции нет); `*_symm.*` — только с `--space-group`.

## Как посмотреть (пошагово)

### VMD

Откройте вкладку Tcl-консоли (**Extensions → Tk Console**) и введите
(папка `results` уже есть в проекте):

```tcl
mol new results/cell.pdb
mol addfile results/critical_points.pdb
```

Или через меню: **File → New Molecule…** → выберите `cell.pdb` → **Load**,
затем **File → Load Molecule…** → `critical_points.pdb`.

Покрасить точки по типам:
**Graphics → Representations → Coloring method → Color by → Resname** —
и выбирайте `CPM1`, `CPP1`, `CPP3`, `CPN3`.

Если в списке resname обрезаны до трёх букв (`CPM`, `CPP`, `CPN` — так делают
некоторые readers), различайте типы по **Segname** (`color by → Segname`):
там полные теги `CPM1/CPP1/CPP3/CPN3`.

### JSmol

Откройте JSmol и введите (путь — от корня проекта):

```
load results/cell.pdb
load results/critical_points.pdb
```

Покрасить по типам:

```
select CPM1; color red;     # связи
select CPP1; color green;   # кольца
select CPP3; color blue;    # каркас
select CPN3; color yellow;  # атомы
```

Если JSmol видит resname только в трёхбуквенном виде, замените имена
на `CPM`, `CPP`, `CPN` (тогда `CPP1` и `CPP3` не различить по resname —
используйте REMARK-строки или `property`).

### VESTA

**File → Import Data…** → выберите `cell.pdb` → **Open**.
Повторите то же самое для `critical_points.pdb` — точки лягут ровно поверх
структуры (координаты одни и те же).

## Bond paths (линии связей)

Для каждой точки связи `(3,-1)` скрипт строит линии по двум независимым
критериям.

### `crystal_BPs.pdb` — найденные аттракторы

В блоке `SEARCH OF BOND PATH ATTRACTORS` TOPOND явно печатает найденные
`(3,-3)`-аттракторы. Скрипт берёт **только** те из них, чей terminus-атом
присутствует в полной таблице `CLUSTER OF ATOMS AROUND THE CP` (все 10 строк,
а не только первые две). На новом файле это даёт **35 линий**: 5 «чужих»
аттракторов (CP 46→47, CP 50→21, CP 71→89/85, CP 72→93) отбрасываются и
перечисляются в `summary.txt`.

Линия идёт от BCP к координате найденного `(3,-3)`-аттрактора, а не к самому
атому. 9 линий заканчиваются на атомах из строк 3–10 кластера — они остаются,
потому что атом присутствует в таблице.

### `calc_BPs.pdb` — достроенные линии

Если для BCP не найден хотя бы один из двух ближайших атомов (первые две
строки кластера), недостающие добавляются при условиях:

- его ещё нет в `crystal_BPs`;
- угол `BCP → атом1 / BCP → атом2` не меньше `--bp-angle` (по умолчанию
  **140°**).

На новом файле это даёт **53 линии**. BCP с углом меньше порога (например,
CP 41: 44.6°, CP 46: 84.7°, CP 50: 66.5°) в `calc_BPs` не попадают; их список
с углами есть в `summary.txt`.

### Формат и просмотр

Обе линии записываются облаком точек с шагом **0.05 Å** (концы включены).
`crystal_BPs.pdb`: resname `CBP`, SEGID `CRYS`; `calc_BPs.pdb`: resname `KBP`,
SEGID `CALC`. Для каждой линии пишется `REMARK` с номером CP, типом, номером
атома, длиной, углом и (для симметрии) номером операции.

```tcl
mol new results/cell.pdb
mol new results/crystal_BPs.pdb
mol new results/calc_BPs.pdb
```

Для файлов связей: **Graphics → Representations → Drawing Method → Points**
(или `VDW` с малым радиусом). Различать линии: **Coloring method → Residue**
(resseq = номер линии) или **Color by → Segname** (`CRYS` / `CALC`).

В JSmol: `load results/crystal_BPs.pdb`, `{points 2}`. В VESTA:
**File → Import Data…** → нужный `*_BPs.pdb`.

## Важно про `--align`: если точки «смещены» относительно атомов

**Признак проблемы:** в VMD/JSmol критические точки висят в пустоте рядом с
структурой или вылезают за её пределы.

**Причина.** CRYSTAL печатает атомы, центрируя их вокруг начала координат
(z от −7.5 до +7.5 Å), а координаты критических точек записаны в «угловом»
образе ячейки (z от 0 до +15.7 Å). Формально всё правильно — точка и её
атомы лежат в одном месте решётки, просто в разных повторяющихся ячейках.
Но визуализатор рисует **только одну** ячейку атомов, без соседних копий,
и «угловые» точки оказываются в воздухе.

**Решение — запустить с флагом `--align`:**

```bash
python topond_cp_export.py CP_BPs_dedup_final.out --outdir results --align
```

Скрипт для каждой точки подберёт сдвиг ровно на целое число векторов решётки
(то есть перенесёт её в тот же образ ячейки, где нарисованы атомы).
Физическое положение точки не меняется — меняется только «номер ячейки».

**Было → стало** (на `CP_BPs_dedup_final.out`):

| Метрика | без `--align` | с `--align` |
|---|---|---|
| медианное расстояние до ближайшего атома | 1.37 Å | 1.25 Å |
| максимальное расстояние | 4.38 Å | 2.68 Å |
| точек дальше 4 Å от любых атомов | 1 из 132 | **0** |
| атомарная NCP лежит на ядре атома | 0.02 Å | 0.02 Å |

По умолчанию координаты остаются **как в исходном файле**, чтобы можно было
сверять их с выводом CRYSTAL17 напрямую. Для просмотра в VMD/JSmol
используйте `--align`.

Флаг `--wrap` (перенос в `[0,1)`) с `--align` несовместим — они делают
разные вещи, вместе не запускаются.

## Размножение по симметрии (`--space-group`)

По умолчанию скрипт экспортирует ровно те критические точки, что напечатаны в
файле (одна асимметричная единица). Чтобы получить **все** CP в полной ячейке,
укажите полный символ пространственной группы Германа–Могена (без пробелов):

```bash
python topond_cp_export.py CP_BPs_dedup_final.out --outdir results --align \
    --space-group P12_1/n1 --symmetry-image shift
```

Скрипт применяет к каждой CP все операции группы `g = R·f + t (mod 1)`,
сворачивает результат в `[0,1)` и убирает совпадающие точки (специальные
позиции и границы ячейки попадают в файл один раз). Дедупликация CP идёт
**в пределах типа**: BCP и RCP в одной координате не схлопываются.

Линии `crystal_BPs` и `calc_BPs` размножаются **согласованной парой**
`(BCP, аттрактор)`: обе точки переносятся одной операцией и одним целым
сдвигом решётки. Совпадающие пары пишутся один раз; `calc`-линия, совпавшая
с `crystal`-линией после симметрии, также отбрасывается.

Результаты пишутся в **отдельные файлы** `*_symm.*` — исходные файлы не
трогаются:

| Файл | Содержимое |
|---|---|
| `critical_points_symm.pdb` | все CP ячейки (+ `REMARK` с номером операции) |
| `critical_points_symm.xyz` | то же в XYZ |
| `critical_points_symm_3m1.xyz` | только BCP (3,-1) |
| `critical_points_symm_3p1.xyz` | только RCP (3,+1) |
| `critical_points_symm_3p3.xyz` | только CCP (3,+3) |
| `critical_points_symm_3m3.xyz` | только NCP (3,-3) |
| `crystal_BPs_symm.pdb` | симметрийные crystal BPs |
| `calc_BPs_symm.pdb` | симметрийные calc BPs |

На `CP_BPs_dedup_final.out` с группой `P12_1/n1` (hall 82, 4 операции):
132 CP → **522 уникальных** (194 BCP + 168 RCP + 108 NCP + 52 CCP);
35 crystal BPs → **140**; 53 calc BPs → **208**.

При `--align` симметрично размноженные CP **центрируются в тот же образ
ячейки**, что и атомы, — иначе `*_symm.*` не совпадали бы с `cell.pdb`.
Линии BPs центрируются в образ атомов всегда, независимо от `--align`.

### Образ ячейки для bond paths (`--symmetry-image`)

Часть симметрийных линий пересекает границу ячейки. Флаг
`--symmetry-image` выбирает, как рисовать такие отрезки (действует **только**
на симметрично размноженные BPs; `--align` не требуется):

| Значение | Поведение |
|---|---|
| `shift` (по умолчанию) | отрезок рисуется как есть; его конец может лежать на периодическом образе ядра — «на одну ячейку дальше» |
| `cut` | отрезок режется по границе ячейки и продолжается на противоположной грани, так что **все** точки остаются внутри образа `cell.pdb` |

В обоих режимах отрезок сначала сводится к кратчайшему (min-image)
смещению, поэтому длина связи физична (≤ ~2.7 Å). `shift` удобно смотреть
целиком, `cut` — когда нужен строго один ячейковый бокс без вылетов.

```bash
python topond_cp_export.py CP_BPs_dedup_final.out --outdir results \
    --space-group P12_1/n1 --symmetry-image cut
```

### Какой символ писать

Используйте **только полный** символ без пробелов. Короткие символы вроде
`P21/n` или `P12_1/n` (без последней `1`) **отклоняются с ошибкой**, потому
что допускают разные установки осей.

> Для ячейки из `CP_BPs_dedup_final.out` правильная установка — `P12_1/n1`
> (hall 82). Каноническая `P12_1/c1` (hall 81) — другая установка осей; её
> операции напрямую не переводят атомы этой ячейки в себя.

Большинство полных символов однозначно определяют установку. Исключение —
40 символов центросимметричных групп, у которых возможны **два начала
координат** (например `P2/n2/n2/n`); из них выбирается стандартное начало
Итальянских таблиц. Если ваша ячейка задана в нестандартном начале, возьмите
`hall_number` из полного списка (флаг `--all-settings`) — но тогда CP из
вывода TOPOND должны быть согласованы с этим началом.

Список команд по одной (канонической) установке на каждую из 230 групп:

```bash
python topond_cp_export.py --list-space-groups
```

Чтобы получить все 530 установок (включая альтернативные, например
`P12_1/n1`, и оба начала координат):

```bash
python topond_cp_export.py --list-space-groups --all-settings
```

Пример из вывода (колонки: номер группы, полный символ, `hall_number`,
число операций, метка выбора осей):

```
# number  full HM symbol (no spaces)       hall  ops
    2    P-1                  2    2
   14    P12_1/c1            81    4  [b1]
   19    P2_12_12_1         115    4
  227    F4_1/d-32/m        525  192  [1]
```

### Допуск совпадения

Точки считаются совпадающими, если их дробные координаты отличаются меньше
чем на `--symmetry-tol` (по умолчанию `1e-3`, то есть ≈0.01 Å). Увеличивайте
только если на границе ячейки появляются дубликаты.

> `--space-group` работает и без `--align`: тогда `*_symm.*` содержат
> точки, свёрнутые в `[0,1)`, как в исходнике, а обычные файлы не меняются.
> Флаг `--symmetry-image` без `--align` **запрещён** (ошибка, код возврата 2).

## Суперячейка (`make_supercell.py`)

`make_supercell.py` — отдельный скрипт. Он **не читает `.out`** и не требует
spglib: на вход подаются уже готовые PDB-файлы из папки `results`.

По умолчанию берутся симметрийно размноженные файлы:

- `cell.pdb` — атомы и исходная ячейка;
- `critical_points_symm.pdb` — все CP;
- `crystal_BPs_symm.pdb`, `calc_BPs_symm.pdb` — линии связей.

Если симметрийных файлов нет, укажите `--source base`: тогда будут взяты
`critical_points.pdb`, `crystal_BPs.pdb`, `calc_BPs.pdb`.

### Быстрый старт

Одна исходная ячейка (`1×1×1`) в папку `results_supercell`:

```bash
python make_supercell.py --indir results --outdir results_supercell
```

Суперячейка `3×3×3` вокруг центра ячейки:

```bash
python make_supercell.py --indir results --outdir results_3x3x3 \
    --center-frac 0.5 0.5 0.5 \
    --range -1.5 1.5 -1.5 1.5 -1.5 1.5
```

Суперячейка `3×3×1`:

```bash
python make_supercell.py --indir results --outdir results_3x3x1 \
    --center-frac 0.5 0.5 0.5 \
    --range -1.5 1.5 -1.5 1.5 -0.5 0.5
```

### Как задаются границы

Границы задаются **не абсолютными координатами**, а смещениями от центра.
Порядок шести чисел всегда один:

```
X0 X1 Y0 Y1 Z0 Z1
```

Итоговый бокс:

```
[lower, upper] = [center + X0, center + X1] ×
                 [center + Y0, center + Y1] ×
                 [center + Z0, center + Z1]
```

Пример `3×3×3` с `center = 0.5 0.5 0.5` и `range = -1.5 1.5 ...`:

- нижняя граница: `0.5 - 1.5 = -1.0`;
- верхняя граница: `0.5 + 1.5 = 2.0`;
- ширина: `3.0` ячейки по каждой оси;
- всего: `3×3×3 = 27` ячеек.

Пример `3×3×1`: по `z` диапазон `-0.5 0.5`, то есть ровно одна ячейка.

### Дробный режим (`--center-frac` / `--range`)

Смещения задаются в долях ячейки и всегда направлены вдоль векторов
`a, b, c`. Значение `1.0` означает одну ячейку.

Значения по умолчанию:

```
--center-frac 0.5 0.5 0.5
--range -0.5 0.5 -0.5 0.5 -0.5 0.5
```

Это ровно одна исходная ячейка. Ширины не обязаны быть целыми: можно
вырезать, например, `2.5×2.5×1` ячейки. В таком случае скрипт предупредит,
что бокс непериодический и его границы могут разрезать молекулы и линии.

### Режим ангстрем (`--center-ang` / `--range-ang`)

Оба флага обязательны вместе. Центр задаётся в декартовых ангстремах,
смещения — тоже в ангстремах. Нельзя смешивать их с `--center-frac` /
`--range`.

Флаг `--ang-axes` выбирает, вдоль каких осей откладывать смещения:

| Значение | Смещения вдоль | Итоговая `CRYST1` |
|---|---|---|
| `cell` (по умолчанию) | векторов `a, b, c` | длины `a,b,c` умножаются на ширины, углы сохраняются |
| `xyz` | глобальных `x, y, z` | орторомбическая, углы `90/90/90` |

Пример, эквивалентный дробному `3×3×3` (центр — середина ячейки):

```bash
python make_supercell.py --indir results --outdir results_3x3x3_ang \
    --center-ang 2.195792 6.973000 7.843313 \
    --range-ang -11.4345 11.4345 -20.919 20.919 -24.024 24.024 \
    --ang-axes cell
```

Пример Cartesian-бокса `20×20×20 Å` вокруг начала координат:

```bash
python make_supercell.py --indir results --outdir results_box20 \
    --center-ang 0 0 0 \
    --range-ang -10 10 -10 10 -10 10 \
    --ang-axes xyz
```

> `--ang-axes xyz` — это **прямоугольный вырез в декартовых координатах**,
> а не строгая периодическая суперячейка. Для моноклинной ячейки его грани
> не параллельны векторам решётки. Скрипт всегда пишет об этом
> предупреждение.

### Что получается на выходе

| Файл | Содержимое |
|---|---|
| `cell_supercell.pdb` | атомы, размноженные по боксу, и новая `CRYST1` |
| `critical_points_symm_supercell.pdb` | CP из `critical_points_symm.pdb` |
| `crystal_BPs_symm_supercell.pdb` | crystal bond paths |
| `calc_BPs_symm_supercell.pdb` | calc bond paths |
| `summary_supercell.txt` | параметры бокса, счётчики и предупреждения |

При `--source base` имена CP/BPs будут без `_symm`:
`critical_points_supercell.pdb`, `crystal_BPs_supercell.pdb`,
`calc_BPs_supercell.pdb`.

Все координаты сдвигаются так, чтобы нижний угол бокса начинался в `0,0,0`.
При симметричном диапазоне (например, `-1.5 1.5`) выбранный центр оказывается
в геометрическом центре нового бокса; при несимметричном — смещён. Абсолютные
координаты при этом меняются. `CRYST1` всегда пишется с группой `P 1`.

В каждом файле есть строки:

```
REMARK   SUPERCELL mode=... source=...
REMARK   SUPERCELL mode=cell bounds_frac=...
```

Для CP и bond-линий в `REMARK` добавляется номер периодического образа
`cell=(tx,ty,tz)`. Это удобно для отладки: видно, из какой трансляции взята
точка.

### Счётчики и обрезание линий

Атомы, CP и **точки** bond paths размножаются поточечно. Поэтому их число
масштабируется ровно как объём бокса: для `3×3×3` получается в 27 раз больше.

Линии bond paths могут пересекать границу бокса. В этом случае линия режется
на границе, и её части попадают в разные периодические образы. Поэтому в
summary для BPs указаны **сегменты** и **точки**:

- `segments` — число кусков линий в выходном файле;
- `dots` — число точек; оно масштабируется ровно.

Для одной ячейки (`1×1×1`) на симметрийных файлах:

```
cell_supercell.pdb: 108 atoms
critical_points_symm_supercell.pdb: 522 CP
crystal_BPs_symm_supercell.pdb: 160 segments, 3752 dots
calc_BPs_symm_supercell.pdb: 229 segments, 3924 dots
```

`160` и `229` больше исходных `140` и `208`, потому что часть линий разрезана
границей бокса. Это нормально; число точек при этом не меняется.

### Ограничения и предупреждения

- Некратные ширины в дробном режиме разрешены, но это непериодический вырез.
- `--ang-axes xyz` всегда даёт Cartesian crop, а не суперячейку.
- Если в PDB больше `99999` записей, serial numbers циклически
  перенумеровываются; в summary будет предупреждение.
- Если `CRYST1` в CP/BPs отсутствует или отличается от `cell.pdb`,
  используется решётка из `cell.pdb`, а в summary пишется предупреждение.
- Скрипт требует все четыре входных файла. Если какого-то нет — он завершится
  с ошибкой и перечислит отсутствующие пути.

### Опции `make_supercell.py`

| Опция | По умолчанию | Что делает |
|---|---|---|
| `--indir ПАПКА` | `results` | папка с готовыми PDB |
| `--outdir ПАПКА` | `<indir>_supercell` | папка результатов |
| `--source {symm,base}` | `symm` | брать `*_symm.pdb` или базовые файлы |
| `--center-frac CX CY CZ` | `0.5 0.5 0.5` | центр в дробных координатах |
| `--range X0 X1 Y0 Y1 Z0 Z1` | `-0.5 0.5 -0.5 0.5 -0.5 0.5` | смещения от центра вдоль `a,b,c` |
| `--center-ang CX CY CZ` | нет | центр в ангстремах |
| `--range-ang X0 X1 Y0 Y1 Z0 Z1` | нет | смещения от центра в ангстремах |
| `--ang-axes {cell,xyz}` | `cell` при `--range-ang` | вдоль `a,b,c` или вдоль `x,y,z` |

`--range` и `--range-ang` несовместимы. `--center-ang` и `--range-ang` нужно
указывать только вместе. `--ang-axes` допустим только вместе с
`--range-ang`.

## Все опции `topond_cp_export.py`

```
python topond_cp_export.py ФАЙЛ.out [опции]
```

## Если что-то пошло не так

| Сообщение | Что значит | Что делать |
|---|---|---|
| `ERROR: input file not found` | неверно указан путь к файлу | проверьте имя файла и путь |
| `ERROR: cell not found` | в файле нет блока решётки | убедитесь, что это вывод CRYSTAL17 с TOPOND |
| `ERROR: no cell atoms found` | не нашлась таблица атомов | то же |
| `ERROR: no critical points found` | не нашлись блоки `CP N.` | возможно, критические точки не считались |
| `ERROR: --align requires the lattice` | не нашлась ячейка, выравнивать не к чему | проверьте, что файл полный |
| `ERROR: unknown or non-standard space-group symbol` | дан короткий или несуществующий символ группы | возьмите полный символ из `--list-space-groups` |
| `ERROR: --space-group requires the lattice` | для размножения нужна ячейка, а её в файле нет | проверьте, что файл полный |
| `ERROR: --space-group requires critical points` | размножать нечего: CP не найдены | убедитесь, что TOPOND считался |
| `ERROR: --bp-angle must be between 0 and 180 degrees` | неверный порог угла | задайте угол в диапазоне 0…180 |
| `error: argument --wrap: not allowed with argument --align` | даны два несовместимых флага | выберите один: `--align` **или** `--wrap` |
| `WARNING: after symmetry expansion the number of NCP ...` | после размножения NCP не совпало с числом атомов | проверьте группу/допуск; подробности в `summary.txt` |
| `make_supercell.py: error: --center-ang and --range-ang must be used together` | для режима ангстрем нужны оба флага | добавьте недостающий флаг |
| `make_supercell.py: error: do not mix fractional and angstrom center/range options` | смешаны дробный и ангстремный режимы | используйте либо `--center-frac/--range`, либо `--center-ang/--range-ang` |
| `make_supercell.py: error: --ang-axes is only valid with --range-ang` | `--ang-axes` без режима ангстрем | добавьте `--range-ang` или уберите `--ang-axes` |
| `make_supercell.py: error: --range: upper ...` | верхняя граница не больше нижней | проверьте порядок `X0 X1` (должно быть `X0 < X1`) |
| `ERROR: input file not found: ...` (от `make_supercell.py`) | нет одного из четырёх PDB | проверьте `--indir` и `--source` |
| `ERROR: ...: no bond path dots` | в PDB BPs не найдены атомы/точки | проверьте, что это файл `*_BPs*.pdb` |

Скрипт **не падает** при отсутствии какого-то раздела: он напечатает понятную
ошибку и всё равно создаст то, что удалось распарсить.

## Технические детали (если коротко)

- **Что парсится:** `DIRECT LATTICE VECTOR COMPONENTS` (ячейка),
  таблицы `ATOM N.AT. SHELL …` (атомы), блоки `CP N.` с `CP TYPE` и
  `COORD(AU)`, полная таблица `CLUSTER OF ATOMS AROUND THE CP` (все 10 строк)
  и блок `SEARCH OF BOND PATH ATTRACTORS` (найденные `(3,-3)`, terminus-атом,
  `UNABLE TO FIND`).
- **Единицы:** координаты CP в исходнике в борах, скрипт переводит в ангстремы
  по коэффициенту `1 Bohr = 0.529177210903 Å`.
- **Дедупликация CP:** по ключу `(тип, x, y, z)` с округлением до 6 знаков —
  номер `CP N.` как ключ не используется, потому что он повторяется.
- **`--align`:** перебор целых векторов решётки `(n1,n2,n3) ∈ [-2..2]³`,
  минимизируется расстояние CP → ближайший нарисованный атом
  (функция `align_cp_to_atoms`); без атомов — откат на обёртку в `[-0.5,0.5)`.
- **Bond paths:** `generate_crystal_bond_lines` берёт найденные `(3,-3)` из
  `bp_attractors` и оставляет только те, чей terminus-атом есть в полной
  таблице кластера. `generate_calc_bond_lines` берёт первые две строки
  кластера, отбрасывает уже найденные в crystal и проверяет угол
  `BCP→ядро/ядро` (по умолчанию 140°). `_make_bond_line` переносит BCP в образ
  атомов, сводит конец к кратчайшему периодическому образу и набирает точки
  с шагом `BP_SPACING = 0.05 Å`. `write_bond_lines` пишет `HETATM` с resname
  `CBP`/`KBP`, SEGID `CRYS`/`CALC` и `REMARK` с CP, атомом, длиной и углом.
- **Нюанс про `resname`:** имена `CPM1/CPP1/CPP3/CPN3` — 4 знака, а в PDB поле
  3 знака. 4-й символ записан в колонку 21, поэтому координаты и элемент
  остаются на стандартных позициях; полный тег продублирован в SEGID.
  В VMD/JSmol, читающих только 3 знака, `CPP1` и `CPP3` сливаются в `CPP` —
  различайте их по SEGID (`segname`) или по номеру из `REMARK`.
- **Симметрия:** таблица групп строится из базы spglib
  (`get_spacegroup_type`/`get_symmetry_from_database`). Полный символ без
  пробелов ищется точным совпадением среди всех установок (для канонической
  `--list-space-groups` берётся одна установка на группу); найдя `hall_number`,
  скрипт достаёт операции как `R` (матрица 3×3) и `t` (сдвиг). Точка
  применяется как `g = R·f + t (mod 1)` в дробных координатах
  (функции `symmetry_operations`, `_apply_op`, `expand_cps_by_symmetry`,
  `expand_bond_lines_by_symmetry`). Совпадения отсеиваются по минимальному
  образу с допуском `--symmetry-tol` (`_FracDedup`); значения на границе
  `1.0` схлопываются в `0.0`. CP дедуплицируются **в пределах типа**, линии —
  как пара `(BCP, конец)`; затем пара целиком переносится целым вектором
  решётки в образ атомов (`_atom_image_shift`).
  `--symmetry-image cut` режет отрезок по границе дробной коробки атомов
  (`_frac_box` = `[-0.5,0.5)³`), перенося выступающую часть на противоположную
  грань (`_dots_cut`), так что все точки остаются внутри.
- **Обратное преобразование решётки:** `cart_to_frac` использует
  `(Mᵗ)⁻¹` (векторы решётки хранятся строками, а `frac_to_cart` считает
  `cart = Mᵗ·f`); это критично для моноклинной ячейки (`β ≠ 90°`).
- **Суперячейка:** `make_supercell.py` читает PDB по фиксированным колонкам,
  не меняет `resname/chain/resseq/segid/element`, перенумеровывает только
  `serial`. Дробный бокс задаётся полуинтервалом `[origin, origin+size)`:
  точка попадает в него при `origin <= f < origin+size` (с допуском `1e-9`).
  Для `--ang-axes xyz` сначала считаются дробные границы восьми углов
  Cartesian-бокса, затем перебираются целые трансляции и точки фильтруются
  уже по Cartesian-условию. Bond paths режутся поточечно: каждая точка
  независимо отображается в бокс, поэтому непрерывность внутри бокса
  сохраняется, а линия на границе распадается на сегменты.
